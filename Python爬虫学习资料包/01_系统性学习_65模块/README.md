# Python 爬虫系统性学习

从计算机原理到分布式架构的完整爬虫课程 —— **65 个知识模块 · 49 个代码文件 · 35,390 行代码**，全部实测跑通。

不是「怎么写」的速查手册，而是讲清「**为什么这样写**」，以及**踩坑之后怎么排查**。

---

## 这套课程的特殊之处

### 1. 所有数字都是真实跑出来的

课程里出现的每一个性能对比、每一个比率，都来自本机实际运行。例如：

| 结论 | 实测数据 |
|---|---|
| SQL 注入的真实破坏力 | 拼接法返回**全表 6 条** vs 参数化返回 **0 条** |
| 批量提交 vs 逐条提交 | 快 **9 倍**（0.348 ms/条 → 0.040 ms/条） |
| 向量化 vs for 循环 | 快 **3,160 倍** |
| category 类型省内存 | **93%**（2.71 MB → 0.19 MB） |
| 并发超过拐点的后果 | 吞吐**降 67%**，P95 延迟**涨 1200%** |
| 重试不加抖动的惊群效应 | 瞬时并发峰值 100 vs 加抖动后 **5**（改善 **95%**） |

### 2. 每个坑都保留完整的排查过程

课程不把 bug 静默修掉，而是写成「**❌ 错误做法 → 现象 → 根因 → ✅ 正确做法**」。这些才是真正有价值的部分。几个例子：

- **NFKC 把 `￥`(U+FFE5) 折叠成 `¥`(U+00A5)**，导致人民币被识别成日元 —— 这条规则光读文档学不到，必须真的跑一次才会发现
- **`DetachedInstanceError` 的行为取决于「之前有没有碰过那个属性」** —— 表现为「偶尔报错，重启就好」，排查极难
- **`rowcount` 对 `UPDATE ... SET title = title` 报告 1** —— 它统计的是 WHERE 匹配的行数，不是实际变化的行数
- **脏数据率算出了 133%** —— 一个字段被两条统计路径重复计数
- **模拟 shell form 得出了「相反」的结论** —— 模拟错了机制，比不模拟错得更彻底

### 3. 诚实标注每一条局限

每节课末尾都有「⚠ 局限」段落，明确说明：哪里是模拟的、哪个数字不能迁移、哪个结论只在特定条件下成立。

> 在工程里，一个「不知道边界在哪的正确结论」和一个「错误的结论」同样危险。

## 快速开始

### 阅读课程

直接用浏览器打开：

```
index.html          # 完整课程（65 章节，640 KB）
课程总目录.html      # 总目录：每章 → 对应文件 → 实测数字
```

无需服务器，双击即可。侧边栏支持导航，阅读进度存在 localStorage。

### 验证代码能不能跑（建议第一步就做）

```bash
python3 冒烟测试.py              # 全部测一遍
python3 冒烟测试.py --deps-only  # 只体检依赖，不运行代码
python3 冒烟测试.py --stage 2    # 只测阶段 2
python3 冒烟测试.py --quick      # 跳过耗时超过 60 秒的文件
```

它会先逐个 import 检查依赖（缺失时报出库名 + 用途 + 影响哪些阶段），
再逐个运行课程文件并收集退出码与耗时，最后给出分级结论。
**缺依赖的文件会被跳过而不是算作失败** —— 这样你能清楚区分「环境没装全」和「代码真有问题」。

### 运行代码

阶段 0-4 几乎全是标准库，开箱即跑：

```bash
cd code/stage2_core
python3 21_books_spider_project.py
```

阶段 5-6 需要额外依赖：

```bash
pip3 install --break-system-packages sqlalchemy duckdb polars \
    apscheduler redis plotly pandas
```

> ⚠ 较新的发行版开启了 PEP 668 保护，直接用 `pip install` 会报 `externally-managed-environment`。
> 容器/沙箱环境下加 `--break-system-packages` 是安全且必要的；真实服务器上建议用虚拟环境。

### 运行完整包测试

`code/stage3_concurrent/spiderkit/` 是一个**真正可安装的 Python 包**（8 模块 1682 行 + 696 行测试）：

```bash
cd code/stage3_concurrent/spiderkit
python3 -m pytest tests/ -q     # 55 passed in 1.33s（全部不依赖网络）
```

## 环境说明

课程在 **Ubuntu 22.04 / Python 3.11** 单机沙箱中开发，因此分布式部分做了如下替代，全部在课程内明确标注：

| 需要 | 实际做法 | 差异 |
|---|---|---|
| 真实 Redis 集群 | 优先探测真实 Redis（已验证 7.4.11），不可用时降级到 `MockRedis` | 逻辑结论可信，**性能/内存数字不可迁移** |
| 多台机器 | `multiprocessing` 起真进程 | 没有网络分区、没有时钟漂移 |
| 真实代理 IP | 模拟「快/慢/死」三类代理 | 无法复现真实风控封禁速度 |
| 容器编排 | 生成真实 Dockerfile / compose，但不构建镜像 | 配置正确性可验证，运行时行为未验证 |

### ⚠ 对公开测试服务的依赖

部分课程用 **httpbin.org** 演示 HTTP 协议细节。它是**免费的公开服务**，实测有约 10% 的请求返回 502、偶尔耗时飙到 11 秒。

遭遇它时你会看到这个极具误导性的报错：

```
requests.exceptions.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

它看起来像「JSON 解析写错了」，**实际根因是服务器返回了 HTML 错误页**（不是 JSON）。这是爬虫最典型的失败模式之一 —— **把网络问题误判成代码问题**。

课程第 0.3 节的 `fetch_json()` 函数专门演示了正确做法：只重试可恢复的错误（超时 / 5xx / 429）、指数退避、失败时降级而非崩溃。

**如果你看到 `⚠ 接口不可用...已重试 3 次，跳过本节实测`，那是预期行为**，不是课程坏了。

另外，阶段 2 及之后的课程大量使用 [books.toscrape.com](https://books.toscrape.com/) —— 这是一个**专门用于练习爬虫的公开靶场站**，请放心使用。

## 建议的阅读方式

1. **先跑一遍** —— 看输出，建立直观印象
2. **再读代码** —— 重点看带「踩坑记录」和「为什么」的注释
3. **改参数重跑** —— 把并发数调大、把阈值改小，看行为怎么变

**第 3 步最重要。** 这门课的所有结论都来自「改了什么 → 结果怎么变」的对照。你亲手做一次对照，比读十遍结论有用。
